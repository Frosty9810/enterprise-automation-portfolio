TRUSTGATE / A BOUNDED LOCAL BUILD

Inspect the source.
Then permit the action.

Follow a proposed tool call from registered source values to a policy decision, a local review and a recorded SQLite effect.

Read the original TrustGate blueprint

Synthetic local demonstration. Tenant, actor and reviewer choices are fixture selectors, not authenticated identity. Three fixed tools can read a public policy, create a local review task or stage a note in a local public outbox. Nothing is sent or published. This does not certify general prompt injection resistance.

Loading the local source and tool catalog…

01 / CHOOSE

Start with a concrete proposal

Compare a public read, a reviewed write and a blocked source flow. Source labels and tool grants are registered by the server; the proposal can only bind their existing keys.

02 / TRACE

Inspect the registered inputs

These values and their labels come from the local fixture catalog. Editing the proposal cannot assign a trust label or add a tool grant.

Waiting for the fixture catalog.

03 / PREPARE

Propose a bounded tool call

Preparation records intent and resolves each binding. It performs no tool effect. A command ID identifies immutable intent: use a new ID for a different proposal.

Use tenant, commandId, actor, tool and bindings. Each binding is a sourceId / key pair. Free arguments, labels and role permissions are not accepted.

04 / DECIDE

Inspect the actual decision

Prepare a proposal to see its source-to-argument provenance and policy reasons.

Record a local review

Read the resolved arguments and provenance before approving. This fixture review records a supplied reviewer name; it is not a login or an external approval.

Only a current, ready receipt can execute. Local writes require an approved review.

05 / RECONCILE

Verify what actually happened

Refresh the selected tenant's saved receipts, local effects and linked audit records. Verification checks the locally stored audit chain; it is not an external signature.
