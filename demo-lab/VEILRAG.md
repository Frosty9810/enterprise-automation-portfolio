# VeilRAG: local declared-literal transport boundary

Status: **partial local implementation** of [the VeilRAG blueprint](../47%20Automation%20Blueprints/2026%20Research-to-Production/05-veilrag.md). Run `node demo-lab/run-veilrag.mjs` from the repository root. Run the adverse cases with `node --test demo-lab/veilrag-core.test.mjs` on Node 24 or newer.

The local proxy accepts an explicit list of protected literal values plus query, context, conversation and tool frames. It replaces exact occurrences with consistent random-session aliases, encrypts the reversible map in SQLite using AES-256-GCM, and sends only the sanitized frames and a closed fixture profile to a separate Node process. The child executes a pinned in-memory copy of the public fixture source, receives an empty environment and has no granted filesystem or child-process access under Node's permission model. It receives no raw map, key, source frames, database handle or database path. This is a fixed local fixture, not a hostile-code or OS sandbox, network isolation guarantee, provider integration or trained model. Core/fixture source drift marks saved sessions stale and prevents generation/restoration until a new session is created under the current implementation.

The normal fixture echoes sanitized frames. Two adversarial fixtures emit a declared synthetic name and a foreign-session alias. The parent rejects these outputs before storing or displaying their contents. It scans every generated output for exact declared literal matches and for unresolved alias namespace tokens. Successful generated text remains sanitized in receipts. An explicit restore operation replaces only known aliases for a server-configured recipient and returns restored plaintext only to the explicit local caller; replay may return it again while its audit event remains single. Plaintext restoration is never written into receipt/history/audit data.

## Contract and storage

`protect({tenant,commandId,entities:[{id,value}],frames:{query,context:[string],history:[{role,text}],tools:[{name,args}]},profile})` accepts only `acme` or `beta` synthetic tenant selectors, bounded JSON tool arguments, and `echo`, `leak` or `foreign-alias` fixture profiles. Unknown properties, prototype keys, collisions with the reserved `[[VR:` namespace and declared literals occurring in submitted transport structural labels/argument keys or other unrewritable wire values are rejected. No user-supplied executable, provider URL, key, clock, TTL, grant or arbitrary output is accepted.

`generate({tenant,receiptId})` claims a session once, then asynchronously runs the child fixture. `restore({tenant,receiptId,recipient})` reads only its stored and scanned generated output. Configured recipients are `acme-reviewer` and `beta-reviewer` for their respective tenants. These labels are **selectors, not authentication**; this loopback demonstration does not authenticate a human or establish production authorization. Receipt, history, audit and vault-purge methods accept tenant-scoped selectors. The same command and exact intent replay without an additional vault; changed intent conflicts. Generation and restoration replay do not repeat their audit events. A server-process interruption after its durable claim can leave an incomplete session with no automatic retry: start a new command explicitly. The UI labels that persisted state as a claimed, unconfirmed result rather than live process activity. Use **Prepare a fresh session for these frames**, then protect explicitly, to create a new command while preserving source frames. Ordinary unchanged retries retain their original identity.

A generator-child failure observed by the running server is recorded as blocked (`generator_failed`); it is the server interruption, rather than every child failure, that can leave a claimed result unconfirmed.

SQLite stores encrypted maps and sanitized frames/output. An HMAC of request intent supports exact replay without an unkeyed hash of the protected input. AES-GCM authenticates session, tenant, intent and expiry metadata. Protected occurrences in source-frame content are stored as aliases; the reversible map is encrypted and restored output is not written back. Protocol metadata, tenant/command labels, timestamps, statuses, opaque IDs and digests remain plaintext and are not confidential. Their incidental bytes may match a declared literal (for example a year or a metadata-key name); this is not a promise that every database byte is free of every declared substring. The complete outbound child DTO is separately checked for every declared literal, including structural keys, before persistence and generation. A SHA-256 linked local audit detects ordinary modification, missing receipts and ciphertext changes. It is **not a signed or externally anchored ledger**: a database administrator can rewrite a complete chain or restore an older complete database snapshot. SQLite backups and disk remanence are outside the purge guarantee.

Factory-only options to `veilRag(db,{key,clock,ttlMs})` or `openVeilRag(path,options)` accept a 32-byte Buffer, trusted millisecond clock function and bounded TTL. Defaults use a process-memory key and 15-minute lifetime. The key is never placed in an environment variable, CLI argument, receipt or log. Restarting with a fresh default key cannot restore earlier sessions. Tests can supply the same Buffer to verify encrypted file persistence; production key management is unfinished. Expired sessions fail closed even on replay and omit transport/output from their public receipt. The first operation that observes expiry commits a metadata-only expiration event before its own transaction, including when restoration is subsequently rejected. This permanent observation survives a backward wall-clock adjustment and same-key process reopen; purge honors it even when the clock has moved backward. Each synchronous operation uses one sampled trusted timestamp; asynchronous generator completion samples again before accepting output. The clock remains a trusted local dependency: a clock that never reaches the deadline cannot provide an expiry observation, and an administrator restoring an older complete database snapshot can remove that observation. `purge({tenant})` removes expired ciphertext once and records a metadata-only event; it does not delete the append-only audit or sanitized evidence. No timer promises secure physical erasure.

## Evidence and remaining scope

Fixtures cover exact alias consistency, longest-first overlap handling, one-pass reconstruction, nested tool values, structural-key leaks, malformed/oversized input, duplicate commands, concurrent generation, unauthorized recipient selectors, expiry and purge, encrypted SQLite restart, lost keys, ciphertext/receipt/audit corruption and transactional rollback. The executable runner reports one generated/restored fixture and two blocked adversarial fixtures. These are fixture checks, **not privacy recall, answer utility, latency or model-quality benchmarks**.

Matching is exact, case-sensitive JavaScript Unicode text without normalization. Alternative case, Unicode normalization, encodings, partial identifiers, undeclared sensitive strings, semantic clues and inference attacks can pass through. There is no automatic NER/SLM detector, Presidio layer, vector retrieval, external generator acceptance, authenticated reviewer, privacy guarantee, key vault integration or research benchmark. The blueprint's hard external privacy constraint remains unverified and external transmission remains disabled. Use synthetic/public fixtures only until detection coverage, authentication, key management, retention, provider isolation and independently measured privacy/utility acceptance exist.
