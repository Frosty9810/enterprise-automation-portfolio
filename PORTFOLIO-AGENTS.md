# Portfolio specialist workflow and governor

Use this workflow when asking Codex to develop or review this portfolio. It describes actual AI delegation within a Codex task; the local `npm run govern` command is the deterministic cross-check layer, not an LLM agent runtime.

## Coordinator (main Codex agent)

1. State a bounded objective, changed project IDs, acceptance criteria and local-only constraints.
2. Assign distinct, non-overlapping ownership to implementation specialists. Each must return changed files, checks, limitations and unresolved findings. Do not allow concurrent writes to the same file.
3. Assign independent reviewers after the implementation is concrete. Reviewers inspect evidence and may reject it; they do not certify their own patch.
4. Resolve blocker/high-severity findings. Record deferred lower-severity findings with a reason.
5. Stop editing, run `npm run govern` from demo-lab, then evaluate the report as governor. Changed sources invalidate approval.
6. Approve only the explicitly checked local scope. Report model integration, hosted n8n/GHL acceptance and human review separately. Never deploy or merge because a local governor is green.

## AI specialists

- Implementation: implement bounded domain changes, preserve public/private boundaries, document concrete examples and limitations.
- Reliability reviewer: cross-check adverse cases, duplicate actions, failure handling, evidence freshness and claimed metrics. Return file/line, severity, reproducible evidence and the required correction.
- Presentation reviewer: inspect the actual UI, readability, navigation, examples and the accuracy of capability claims. Distinguish visual observation from automated DOM checks.
- Governor (coordinator): reconcile disagreements against requirements and evidence. Decisions: approve the reviewed local scope, request changes, or mark evidence incomplete. Never overrule a reproducible failure just to finish a cycle.

The current task used two independent AI reviewers (governor_audit and presentation_audit), with implementation and governor responsibility retained by the coordinator. Their findings identified incomplete source hashing, stale green reports, narrow approval scope and overwritten browser history. They were observations from actual subagents, not generated by the deterministic runner.

## Executable cross-check workflow

Run `npm run govern` in demo-lab. Three isolated child processes run in parallel:

1. Implementation worker: Node syntax checks and execution of the nine engineering fixtures.
2. Regression worker: the complete local Node suite, including the 27 automation and 20 human-tool checks already represented in it.
3. Presentation worker: renders and exercises every engineering example using the DOM harness. This is not a screenshot/accessibility audit.

The governor requires exactly one passing report per role, positive check counts, successful exits and the same recursive source snapshot before and after review. It publishes an incomplete state at startup, writes reports atomically, and limits workers to 90 seconds. The endpoint `/api/governance` compares the recorded snapshot with current files on every request; stale approval is shown as incomplete evidence. A lock prevents overlapping runs. A crashed run may leave a lock: inspect `.runtime/governor.lock` and confirm the owner is no longer running before removing it.

Snapshot scope: repository code/config files (JS/TS/Python/HTML/CSS/JSON); runtime directories, dependencies, reports and generated review JSON are excluded. This is source identity, not a signed approval or authenticated reviewer ledger. The runner does not make model calls, modify project code, merge, deploy, or independently conduct an AI critique. Rerun after source edits. AI-review findings still require the coordinator to resolve them.

## Example rejection story

Change a repair source after its test evidence was recorded. The regression worker detects mismatched repair hashes. The governor returns needs-work and the UI retains the failed role and logs. Correct the source or regenerate legitimate repair evidence with `node demo-lab/verify-repair.mjs`, rerun the tests, then rerun the governor. Never edit a result flag to force approval.

## Governor verification — September 12

Two independent Codex reviewers audited the design; the governor reviewer confirmed closure of the stored-approval integrity finding after the fix. The local gate passed 42 implementation checks, 68 regression checks and nine engineering presentation checks. A real API drift probe demonstrated approved-local-checks → incomplete-evidence after a temporary source addition → approved-local-checks after restoring the exact source snapshot. No permanent source modification was made by that probe.
